# MAZUNIN / SCIENCE — первая публичная версия

Сайт подготовлен для отдельного репозитория GitHub **mazunin-science** и адреса **https://mazunin.science/**. Все файлы сейчас локальные. Репозиторий на GitHub не создавался, файлы не отправлялись, GitHub Pages и DNS не изменялись.

## Утверждённое содержание

- Образование → «Молекулярная биология»: https://fresll.github.io/molbio/
- Исследовательские ресурсы → PGT-mt Atlas: https://fresll.github.io/pgt-mt-atlas/ru/
- Modicum, «Обновления» и «О платформе» — в разработке. Нет вымышленных материалов, новостей или достижений.

Два ресурса открыты и проверены в браузере 26 октября 2026 года. Их содержимое не копируется в главную страницу. Сохранены три интерактивных листа, архитектурные миниатюры, Helvetica и утверждённая палитра.

## Локальная проверка

Нужен Node.js 22 или новее. Установка пакетов не требуется.

```sh
node scripts/build.mjs
node scripts/check-release.mjs
```

`dist/` — готовый статический сайт. В нём только главная, assets, 404, robots, sitemap, CNAME и .nojekyll. Варианты A/B, дизайн-галерея, скриншоты и рабочие документы в публикацию не входят.

В основном рабочем проекте можно запустить:

```sh
PORT=4174 node serve.mjs dist
```

И открыть http://127.0.0.1:4174/. В чистой папке репозитория, где нет вспомогательного сервера, при установленном Python 3:

```sh
python3 -m http.server 4174 --bind 127.0.0.1 --directory dist
```

Главная работает из корня домена; пути к assets относительные. Якорная навигация и переключение RU / EN не зависят от имени репозитория. Есть обычные ссылки на действующие ресурсы и резервные ссылки при отключённом JavaScript. Для раскрытия листов нужен JavaScript.

## Чистая папка будущего репозитория

В основном рабочем проекте команда `node scripts/prepare-repository.mjs` создаёт `release/mazunin-science/`. Это самостоятельный комплект исходников для нового репозитория, без Git-метаданных, черновиков и скриншотов. В комплекте есть сборка, проверка и workflow. Не редактируйте сгенерированную папку параллельно исходному проекту: правки вносите в проект, затем пересоздавайте комплект.

## После отдельного разрешения на публикацию

1. Создать отдельный репозиторий `mazunin-science` в нужном аккаунте GitHub. Для GitHub Free использовать публичный репозиторий. Загрузить **содержимое** чистой папки `release/mazunin-science/`, включая `.github/` и `.gitignore`, в ветку `main`. Существующие Molbio и Atlas не менять. Настройку remote и отправку кода выполнить только после проверки владельца репозитория.
2. В `Settings → Pages → Build and deployment → Source` выбрать **GitHub Actions**. Workflow `.github/workflows/pages.yml` запускается **только вручную** из `Actions → Publish MAZUNIN SCIENCE → Run workflow` на ветке `main`. На push и pull request публикация не запускается. Workflow собирает и проверяет `dist/`, затем публикует только эту папку.
3. После согласования подключения домена указать **mazunin.science** в `Settings → Pages → Custom domain`. Для Actions файл CNAME сам по себе не настраивает домен: это отдельно выполняется в Settings. Подготовленный CNAME в сборке не является DNS-записью и ничего не подключает автоматически.
4. В отдельном согласованном шаге изменить DNS у регистратора по актуальной инструкции GitHub. Для корня домена поддерживаются ALIAS/ANAME либо A-записи GitHub Pages. После подтверждения домена и выпуска сертификата включить **Enforce HTTPS**, проверить https://mazunin.science/ на телефоне и компьютере, переходы к обоим ресурсам и глубокие ссылки `/#education`, `/#research`.

Выбор источника и запуск workflow описаны в [GitHub Docs](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site). Порядок настройки Custom domain, DNS и HTTPS — в [инструкции GitHub по собственному домену](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/managing-a-custom-domain-for-your-github-pages-site). Значения DNS следует сверить непосредственно перед подключением; в рамках подготовки DNS не меняется.

До отдельного разрешения не запускать workflow публикации, не включать Pages и не менять DNS.
